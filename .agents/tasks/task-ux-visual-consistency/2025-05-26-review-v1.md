# Visual consistency pass: sliders, toggles, checkboxes, and mouse-lock safety

This change normalizes the visual language of form controls across several views. Raw `<input type="range">` elements in HotkeysView and CustomizeView are replaced with the shared `cd-slider` component. The `cd-toggle` dimensions and states are tightened. A new `.styled-checkbox` class gives native checkboxes a custom appearance consistent with the rest of the design system. DebugView is migrated to the `unified-page`/`surface` layout. Separately, `window.js` gains a destroyed-window guard for the click-through toggle and a mouse-lock release in the emergency-quit path.

**Watch for:** The `styled-checkbox` class is applied in MainView but the CSS rule lives in `unifiedPageStyles`, which MainView does not import — the checkbox will render unstyled (confirmed). The `cd-slider` value display has no decimal formatting, so HotkeysView sliders with fractional steps (0.05, 0.01) will show raw floating-point numbers (confirmed). The toggle dot geometry is slightly asymmetric at the ON position (likely cosmetic-only).

## High-level view

The `.styled-checkbox` addition in `sharedPageStyles.js` works for DebugView and HistoryView because both import `unifiedPageStyles`. MainView does not import those styles, so the class has no effect there — the checkbox falls back to the existing `accent-color` styling from MainView's own `.checkbox-group input[type='checkbox']` rule, creating a visual inconsistency between views.

The `cd-toggle` resizing from 36x20 to 40x22 with a visible border in the OFF state improves distinction from the background. The dot travel distance (18px) creates a 1px gap against the right border in ON state versus 3px on the left, which may look pinched on retina screens.

The slider migration removes duplicated CSS from both consumer views and delegates to `cd-slider`, but the component lacks decimal formatting for its value display. HotkeysView passes fractional steps (0.05, 0.01) that will produce floating-point display artifacts.

The mouse-lock safety fix ensures emergency-quit releases `setIgnoreMouseEvents` so the OS cursor cannot be trapped if the app exits while click-through is active.

## styled-checkbox scope gap in MainView

The `.styled-checkbox` rule is defined inside `unifiedPageStyles` in `sharedPageStyles.js`. DebugView and HistoryView both compose this stylesheet into their `static styles` array, so their shadow DOM contains the rule. MainView does not import `unifiedPageStyles` — its `static styles` block is self-contained with its own `css` template literal. Adding `class="styled-checkbox"` to the AI Hearing checkbox has no effect: the class attribute is present in the DOM but no matching CSS rule exists in that component's shadow root.

The existing `.checkbox-group input[type='checkbox']` selector in MainView still applies (it targets by element type, not class), so the checkbox won't look broken — it just won't match the styled appearance of the same class in other views.

Fix: either import and spread `unifiedPageStyles` into MainView's styles array, or copy the `.styled-checkbox` rules into MainView's local CSS.

## Slider decimal formatting

`cd-slider` displays the value with `${this.value}`, which depends on JavaScript's default number-to-string conversion. For integer-step sliders (font size, font weight, move step) this is fine. For fractional-step sliders in HotkeysView:

```
Scale (step 0.05): could display 0.7500000000000001
Scale Step (step 0.01): could display 0.060000000000000005
```

The old `_renderSlider` accepted a `decimals` parameter and called `.toFixed(decimals)` on the displayed value. That formatting was lost in the migration to `cd-slider`. The `decimals` parameter is still passed to `_renderSlider` but is now unused.

A `decimals` property on `cd-slider` (defaulting to auto or undefined) that applies `toFixed` when set would restore parity.

## Toggle geometry

Track: 40px wide, 1px border each side → 38px inner content.  
Dot: 16px wide, positioned at `left: 3px`.

```
OFF:  [3px gap][16px dot][19px gap]    (visual weight toward left)
ON:   [21px gap][16px dot][1px gap]    (dot nearly touching right border)
```

For equal 3px padding on both sides in ON state, the translate should be `38 - 16 - 3 - 3 = 16px`. Current value of 18px pushes the dot 2px too far right. Vertically, the same issue exists: 22px track with 1px border = 20px inner height, dot at `top: 3px` with 16px height = 1px bottom gap.

This is cosmetic and may not be noticeable at the 22px scale, but on high-DPI displays the asymmetry can be perceptible.

## Dead CSS after DebugView migration

Three rules in DebugView's local styles target `.debug-section`:
```css
.debug-section { margin-bottom: var(--space-lg); }
.debug-section h3 { ... }
.debug-section p { ... }
```

The template now uses `<section class="surface">` with `<div class="surface-title">` instead. The old rules are unreachable dead code.
