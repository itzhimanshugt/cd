# Auto Type and Developer sidebar views

Two new sidebar panels expose the typing system's full configuration surface and a developer debugging toolkit. The Auto Type view renders live status, backend selection with availability indicators, a reorderable failover chain, backend health grid, timing sliders, mode toggles, keybind editors, and focus controls. The Developer view provides screenshot capture, a filterable structured log viewer with auto-refresh, a runtime state inspector with expandable sections, performance metrics, and a one-click debug snapshot export. Supporting infrastructure includes a singleton ring-buffer logger with file rotation, a screenshot utility wrapping `webContents.capturePage()`, ten new IPC handlers, a renderer-side `cheatingDaddy.debug` API object, and a new `Alt+S` screenshot hotkey.

**Watch for:** Dead code at module top-level in `window.js` — a summary-logging block that references `keybinds` (a function parameter) was dedented out of its function, making it unreachable dead code at module scope (confirmed). Slider drags in AutoTypeView fire unbounded IPC+disk writes with no debounce (confirmed). The `Alt+S` hotkey may conflict with common shortcuts in target applications (likely).

## High-level view

The Auto Type view is a pure renderer-side component that reads state through the existing `cheatingDaddy.typing` API and subscribes to typing events for live updates. It writes settings back through `setSettings()` on every toggle/slider change, which means rapid slider drags fire IPC calls and disk writes at input-event frequency — no debounce exists.

The Developer view introduces a new IPC surface (`debug:*` namespace, 10 handlers) that gives the renderer full introspection into the main process: memory, CPU, all settings, all keybinds, typing state, and the full log buffer. The view manages three independent auto-refresh timers (2s intervals each) for logs, runtime state, and performance.

The logger is a singleton with a 500-entry ring buffer that also writes synchronously to disk on every log call (`appendFileSync`). File rotation is implemented but the synchronous writes block the event loop proportionally to log frequency.

The `window.js` change dedented a summary-logging block from inside `updateGlobalShortcuts` to module top level, where `keybinds` is undefined. The `|| {}` guard prevents a crash, but the block is now dead code that runs at require time to no effect.

## Dead code at module top-level in window.js

The diff shows a block of code that was previously indented (inside `updateGlobalShortcuts`) being dedented to the module's top level:

```javascript
// At module top-level now:
try {
    const summary = {};
    for (const [k, v] of Object.entries(keybinds || {})) { ... }
    console.log('Global shortcuts registration summary:', summary);
} catch (e) { /* non-fatal */ }
```

`keybinds` is not defined at module scope — it's a parameter of `updateGlobalShortcuts`. The `|| {}` guard means `Object.entries(undefined || {})` returns `[]`, so the loop body never executes and no crash occurs. But the block is dead: it can never log a shortcut registration summary because `keybinds` will always be falsy here. The base code already had suspicious indentation (4-space indent at module level), but the change made it worse by "fixing" the indent to zero while leaving the code in place. Move it back inside `updateGlobalShortcuts` at the end of the function, or delete it.

## Settings writes without debounce

AutoTypeView binds `@input` (not `@change`) on all range sliders to handlers like `_onSpeedChange`, `_onJitterChange`, etc. Each fires `_updateSetting` which immediately calls `window.cheatingDaddy.typing.setSettings({ [key]: value })`. On a slider drag from 80 to 200 WPM, this produces ~120 IPC round-trips, each potentially writing to disk via `storage.setTypingSettings`. The number inputs correctly use `@change` (fires on blur/enter), but the six range sliders all use `@input`. A 150ms debounce on `_updateSetting` would collapse these into a single write per drag gesture.

## Synchronous logging I/O

Every call to `logger.info()` (or any level) goes through `_writeToFile` which calls `fs.appendFileSync`. In the main Electron process, this blocks the event loop for each log entry. The rotation check (`this._currentSize >= this._maxFileSize`) triggers `_rotateFiles` which performs multiple synchronous `renameSync` operations. Under high-frequency logging (typing events at character granularity, IPC debug calls) the cumulative blocking time could cause visible stutter. Switching to `fs.appendFile` with a write queue or batching writes on a short timer (50ms) would eliminate the risk without changing the API.

## Logger child level drift

`child(category)` creates a new Logger instance and copies `this._minLevel` by value:

```javascript
child(category) {
    const child = new Logger();
    child._entries = this._entries; // shared reference
    child._minLevel = this._minLevel; // copied by value
    child._category = category;
    return child;
}
```

If the singleton's level is later changed via `debug:set-log-level`, previously-created children retain the old level. Since children share the `_entries` array, their writes still land in the same buffer — but they may filter differently than expected. Fix by storing level on the shared entries array or having children delegate to the parent's level getter.

## Alt+S hotkey scope

The screenshot hotkey is registered as a global shortcut via `globalShortcut.register`, meaning it captures the key combination system-wide regardless of which window is focused. `Alt+S` collides with common app shortcuts ("Save As" in Firefox, menu mnemonics in many Windows apps). The other typing hotkeys use heavier modifiers (`Ctrl+Shift+F/G/X`) to avoid this. Consider `Ctrl+Shift+S` or `Ctrl+Alt+S` for consistency, or make it configurable-only with no default.
