# Native window opacity removal in favor of CSS-driven transparency

This change removes the dead native `win.setOpacity()` system — IPC handler, state-patch branch, hard-limit constants, keybind registrations, renderer listener, and toast — and replaces the two old `opacityUp`/`opacityDown` hotkeys with four granular CSS-driven ones: `fontOpacityUp`, `fontOpacityDown`, `bgOpacityUp`, `bgOpacityDown`. The old system faded the entire BrowserWindow including text, which made content unreadable at low values; the new architecture controls text alpha and background alpha independently via CSS custom properties and the existing `backgroundTransparency` preference. Scroll keybinds (`scrollUp`/`scrollDown`) are reassigned from `Cmd/Ctrl+[`/`]` to `Cmd/Ctrl+Shift+Up`/`Down` to free up the bracket keys for font opacity.

**Watch for:** Residual `opacity`, `opacityStep`, and `opacityEnabled` fields in `storage.js` defaults that are no longer consumed (confirmed). The new font/bg opacity hotkeys have no feature-toggle guard, unlike their predecessor which was gated by `opacityEnabled` (confirmed).

## High-level view

The main-process window module (`window.js`) drops `applyOpacity`, the `window:set-opacity` IPC handler, and the opacity branch in `_applyStatePatch`. The hard-limit constants for opacity are removed, but the matching defaults in `storage.js` (`opacity`, `opacityStep`, `opacityMin`, `opacityMax`, `opacityEnabled`) survive — dead fields that will persist in users' config files with no code path reading them.

The renderer (`renderer.js`) removes `setOpacity`, `onOpacityChanged`, and the `opacity-changed` toast listener. The `getDefaultKeybinds` map swaps the two old opacity entries for four new ones and reassigns scroll to arrow keys.

The hotkeys UI (`HotkeysView.js`) replaces the two old hotkey entries with four new entries and drops the Opacity/Opacity Step sliders. The new entries use `toggle: null`, meaning they cannot be individually disabled from the settings pane — a behavioral change from the old `opacityEnabled` guard.

## Dead storage fields in `storage.js`

The diff touches `window.js`, `renderer.js`, and `HotkeysView.js` but not `storage.js`. These defaults remain:

```javascript
opacity: 1.0,
opacityMin: 0.0,
opacityMax: 1.0,
opacityStep: 0.05,
opacityEnabled: true,
```

No code path reads `opacityStep`, `opacityMin`, or `opacityMax` anymore. `opacityEnabled` was the toggle guard for the old hotkeys; now nothing consumes it.

## Keybind reassignment and collision space

The bracket keys previously served double duty: `Cmd+[`/`]` was `scrollUp`/`scrollDown`, while `Cmd+Shift+[`/`]` was `opacityUp`/`opacityDown`. After this change:

- `Cmd+[`/`]` (or `Ctrl+[`/`]`) → `fontOpacityDown`/`fontOpacityUp`
- `Cmd+Shift+[`/`]` (or `Ctrl+Shift+[`/`]`) → `bgOpacityDown`/`bgOpacityUp`
- `Cmd+Shift+Up`/`Down` (or `Ctrl+Shift+Up`/`Down`) → `scrollUp`/`scrollDown`

## Loss of the feature-toggle guard

The old system respected `opacityEnabled`:

```javascript
// Old HotkeysView entry (removed)
{ id: 'opacityUp', ..., toggle: 'opacityEnabled' }
```

The replacement entries all use `toggle: null`. In `window.js`, the `fontOpacityUp`/`Down` and `bgOpacityUp`/`Down` registrations are unconditional (not wrapped in an `if (winState().opacityEnabled !== false)` block like zoom/scale are). If any user had disabled opacity hotkeys, they can no longer do so.

Additionally, font opacity is now only adjustable via hotkey — no slider equivalent exists in the UI, unlike background opacity which has the Customize view's transparency slider.
